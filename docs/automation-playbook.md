# OpenReply automation playbook

How YOYAKU runs comment-to-DM and keyword-to-DM automations on Instagram: the
house style, which trigger fits which post, and how release posts are wired.
Read this before creating, generating or editing any `Automation` row, by hand,
by SQL, by CSV import or from a cron.

## House style (Ben, 2026-11-01)

> « J'aime bien que ça envoie un message, oui. Mais je trouve que ça a fait le
> commentaire qui sert à rien. » · « Je n'aime pas quand ça commente chaque
> commentaire. »

1. **Private DM: yes. Public reply under the comment: never.**
   `publicReplyEnabled` stays `false` on every automation. Leave
   `publicReplyMessages` empty on new rows. The schema, `POST /api/automations`,
   the release cron and the calendar cron all default to `false`; the only ways
   to turn it on are the dashboard checkbox, a CSV import with a non-empty
   `publicReply` column, or a hand-written SQL insert. Do none of them.
2. **Two-step DM.** `openingDmEnabled = true`: the private reply is a short
   message with one button; the tap delivers the reveal DM with the link
   buttons. This is the shape of every generated campaign.
3. **Copy rules** (enforced for generated copy by `lib/copy/copy-linter.ts`,
   voice in `lib/copy/yoyaku-patterns.ts`): facts only, no emoji, no em/en
   dash, no price, no mention of AI or automation, no invented name. Meta
   limits: body 640 characters, button title 20, at most 3 buttons.
4. **Links are tracked** (`TrackedLink`, served as `/r/<slug>`) and carry UTM:
   `utm_source=instagram&utm_medium=dm&utm_campaign=<campaign-slug>`.
5. **No follow gate** unless the goal is followers. `requireFollow` adds a step
   and loses people when the goal is an email or a sale.
6. **Barcelona (BCN): double text, English then Spanish, on every message and
   every button; both versions say the same thing.** English comes first, then
   a blank line, then Spanish. The rule covers the opening DM, the reveal DM
   and each button label (`Yes / Sí`, `Join / Únete`), and applies to both
   triggers: the `COMMENT` campaign and the `BCN` keyword `INBOUND_DM` one. A
   keyword or a `catnoTag` carrying `BCN` or `barcelona` is the marker.
   `lib/copy/copy-linter.ts` carries the check: `isBarcelonaAutomation` reads
   the marker off `keywords` / `catnoTag`, and `lintBarcelonaCampaign` verifies
   the English half comes first, a Spanish half follows, and every button is
   `English / Spanish`. Run it on the copy before saving a BCN campaign.

   > « the openreply for BCN have to be in english and in spanish too !
   > remember this rule double text » — Ben, 2026-11-01

## Which trigger

Anyone who comments receives the private message. YOYAKU never asks for a
specific word, so a comment campaign is `matchAnyWord = true` unless someone
deliberately narrows it. A word is spoken in the caption only for an
exception, and that exception is a business decision, not the default.

| Situation | Trigger | Notes |
|---|---|---|
| Our own post, any comment should get the DM | `COMMENT`, `matchAnyWord = true` | The default. Bound to one post (`postId`). |
| Our own post, only a keyword should get the DM | `COMMENT`, `keywords = [KEYWORD]` | Exception, chosen explicitly. |
| Story, bio, or a post published by another account (collab) | `INBOUND_DM`, one exact keyword | See `docs/inbound-dm-campaigns.md`. One active owner per keyword and account. |
| Future post or reel identified by a printed catalogue hashtag | `COMMENT`, `pendingNextReel`, `catnoTag` | Manual campaign in the builder. See `docs/catalogue-campaigns.md`. |
| Release post | Generated by `/api/cron/sync-releases` | See below. |

A keyword used in a caption must also be listed in yoyaku-marketing
`lib/content-rules.json` `cta_keywords`, or `content-lint` blocks the caption.

## Release posts (automated)

- `/api/cron/sync-releases` calls `createGeneratedCampaign()`
  (`lib/automations/create-generated.ts`): the campaign is born **inactive**
  (a human reviews and activates it), `pendingNextReel = true`,
  `catnoTag = <catno>`, `matchAnyWord = true`, opening DM on, public reply off.
  `/api/cron/sync-calendar-intents` follows the same rule for calendar posts:
  a Calendar intent carrying a CTA keyword creates a campaign with
  `matchAnyWord = true` and `keywords = []`, and the keyword value is never
  compared, so a Calendar-side rename does not deactivate an active campaign.
- **Binding is by hashtag.** The attach cron binds a pending campaign only to
  the first feed or reels media whose caption contains `#<catnoTag>`; no exact
  match fails closed. So the caption must carry `#<catno>`, and the campaign
  must exist before the post is published.
- **Post already published without the hashtag:** bind it by hand under the
  same guard the binder uses:
  `UPDATE "Automation" SET "postId"='<media id>', "postUrl"='<permalink>', "pendingNextReel"=false WHERE id='<id>' AND "pendingNextReel"=true;`
  Comments already posted are picked up by the comment reconciler within
  `COMMENT_POLL_LOOKBACK_HOURS` (default 72 h).

## Hand-made campaign (store news, event, announcement)

1. Create it from the dashboard or `POST /api/automations` with the public
   reply unchecked. An SQL insert copies the shape of `createGeneratedCampaign`
   and sets `publicReplyEnabled = false` explicitly.
2. OpenReply does not collect email addresses. To build a list, the button
   opens the site's signup form (for Barcelona: `https://yoyaku.io/barcelona/#signup`,
   list 22; `utm_source=instagram` makes the referrer `barcelona-landing-ig`).
3. Before the post goes out: send the keyword in DM from a team account and
   check the DM, its buttons, and that `/r/<slug>` answers 302 to the right
   page. Test clicks count in the stats.

## Kill switches and checks

- Stop a campaign: `UPDATE "Automation" SET "isActive"=false WHERE id='<id>';`
  The worker reloads automations on every job, so a change applies to the next
  comment.
- Check that nothing is commented publicly:
  `SELECT count(*) FROM "DmLog" WHERE "automationId"='<id>' AND "publicReplySentAt" IS NOT NULL;`
  must stay at its previous value.
- Results: `DmLog` rows per automation (opening DMs sent, reveals delivered),
  `LinkClick` per tracked link, and the signups on the destination list.
